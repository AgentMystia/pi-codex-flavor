# 能力覆盖与兼容边界

本报告独立于运行安装包。面向标准 Arch Linux 上的日常开发，验证使用模拟 provider。

| 方案能力 | 实现与边界 |
|---|---|
| 用户提问 | 同步/异步、1–3 问、推荐说明、自由输入、子代理共用队列、取消/过期/失效、标准 Pi TUI/RPC；无渠道返回 unavailable |
| 计划/任务 | `/plan` 切换只读计划模式（对齐 Codex 协作模式：模式指令、update_plan 拒绝、阻塞提问、<proposed_plan> 三选项退出）；计划和 reviewer 强制只读；update_plan、任务、明确决定、最近批准计划持久化 |
| 多代理 | 持续线程、分叉、顺序消息/指导、等待环检测、FIFO 调度、16/64 名额、256 任务、四层委派、中断/关闭/恢复；`/subagent` 会话（仅内存）与全局（agent 目录）两层模型/思考档位配置，会话层优先，未配置时继承；角色昵称寻址、紧凑 wait 状态表与有界输出；子代理为 Pi Agent core + SessionManager，不重复加载扩展 |
| 权限/隔离 | `/permissions` 三档选择：Ask for Approval / Full Access / Read-Only；分支持久化、统一作用于主/子代理和后台；Full Access 放开本机文件/网络且免逐次批准，计划/reviewer 仍只读；执行批准对话移植 Codex 决定集：单次、会话免询问（精确命令内存缓存）、命令前缀持久化规则（agent 目录 execpolicy.json，按提升模式隔离、禁用危险前导）、拒绝；外部工具与 always 文件写入同样支持会话缓存；Arch 全隔离需要物理机实测 |
| 终端 | 官方 ExecCommandToolOutput 文本格式、首尾截断、短整数 session_id、max_output_tokens、正文工具卡；结构化结果紧凑 JSON 序列化、错误文本 900 字节中段截断、外部扩展输出首尾保留；管道 stdin/stdout/stderr、增量输出、超时、取消、进程组与沙箱清理；不实现原生 PTY |
| 文件修改/恢复 | Codex 标记补丁新增/更新/删除/移动；多文件失败报告已完成部分和差异；Pi write/edit 兼容；统一文件队列、目录 fd 防符号链接竞态、显式恢复、冲突检测；单文件跟踪上限 4 MiB |
| 搜索/图片 | Pi read/ls/schema/renderer，grep/find 使用同一执行器调用现有 rg；图片通过 Pi 自带处理和 model catalog，无额外模型 |
| 验证 | 显式运行选择的项目命令，记录 passed/failed/cancelled/not_run 与运行前后指纹；后续相关文件改动标记 stale；不在启动自动检查 |
| 审阅 | 工作区/暂存/范围 diff、评论、强制只读 reviewer；不自动暂存/重置/提交/合并 |
| 上下文 | 分支增量状态、Pi 主会话压缩后必要状态事件、线程 SessionManager 持久化/明确恢复；空闲子线程可按需复用 Pi 摘要，不做后台模型摘要 |
| 工作流/规则 | 精简 implement/debug/refactor/test/review，按需加载；保留 Pi 系统提示词、根项目规则、技能和已有扩展；深层 AGENTS.md 继续由代理发现 |
| 提示词 | 2026-11-12 最新公开 Codex 提交 c0cc9fc820f6 的 GPT-6.1-Sol 指令模板及角色原文，以删除和必要协议修改移植；完整文本、来源、逐行差异单独交付；显式代码审阅规范按需追加，无自动自我审查 |
| MCP | 复用主会话 Pi 原生 MCP/search/codemode、来源和嵌套权限钩子；外部调用限制输出并独立批准；子代理通过消息向主代理请求额外服务 |
| LSP | 可选且默认无工具/无进程，已有服务器 argv、首次批准、受控只读启动、JSON-RPC、定义/引用/hover/符号/有界诊断、预览后跟踪应用；不执行 command/资源操作 |
| UI | 基于公共 CustomEditor 只定制输入框边框，状态仅出现一次；左侧模式/权限，右侧按需活动，隐藏零计数，继承原生快捷键、运行/滚动指示与 IME 光标；权限菜单选中行/边框/窄屏布局，工具卡和覆盖层；无定时 AI 调用 |

| 兼容目标 | 状态 |
|---|---|
| @earendil-works Pi 1.5.2 / Node 22.19+ | SDK 临时 profile 和模拟 provider 验证 |
| @mariozechner Pi 0.73.1 | 不支持 |
| 标准 Arch Linux | 已在物理机完成沙箱验收 |
| Linux x86_64 / arm64 | seccomp 编码已实现两种 ABI；arm64 尚未运行验证 |
| TUI | 公共组件接入；自动检查窄宽度/中文/长输出，不等同真实终端/IME 人工验收 |
| RPC | 实际 Pi session 标准 dialog API 验证；不自定义 RPC 协议 |

隔离外明确批准执行使用主机环境。其副作用不可自动撤销，强制结束按进程组清理；沙箱内的 PID namespace 才提供脱离进程组后代的内核清理边界。工作区应是普通独立检出：不要把指向工作区外的硬链接或预挂载目录当作可写项目内容。MCP/原生 provider 服务的网络请求不属于本地 shell 网络策略。

## 0.3.0 行为变更

| 范围 | 变更 |
|---|---|
| 执行批准 | 前缀规则只放行单条简单命令；含 `;`、`&`、`|`、重定向、命令替换、反斜杠或换行的命令回到询问，即使其开头匹配已存规则 |
| 终端 | `exec_command` 默认等待 10 秒（250 毫秒至 30 秒），空的 `write_stdin` 轮询至少等待 5 秒，`bash` 兼容工具最多等待 30 秒；状态头一行 |
| 补丁 | 首个块可省略 `@@`；空行视为空上下文行；上下文按“精确、忽略行尾空白、忽略首尾空白”依次匹配；`@@` 锚点后取第一处匹配；宽松匹配到的未改动行保留文件原文；无锚点的多处匹配仍拒绝 |
| 结果正文 | `apply_patch`、`restore_changes` 返回 change id 和每个文件的增删行数，diff 留在 `details` 和工具卡；`run_verification` 返回一行结论加首尾截断的输出；`verification_status` 每条一行；线程控制、计划、任务、消息、评审和同步提问返回紧凑确认，不回传模型刚写入的内容 |
| 搜索与读取 | `grep`、`find` 输出相对工作区的路径；`limit` 是整个结果的上限并注明剩余数量；超过 400 列的行只显示预览；`read` 超过结果上限时在行边界截断并给出续读的 offset |
| 持久状态 | 修改记录只存哈希和权限位；修改前的内容按内容哈希存一份（文本按文本存），总量 16 MiB，超出时最旧的先被淘汰，对应修改不可恢复并明确报错；保存只写变化的项；验证记录不保存命令输出；0.3.0 之前内联 base64 的旧记录仍可恢复 |
| 压缩延续 | Pi 压缩后的延续消息只带未完成的计划和任务、未关闭的线程、待答问题以及最近 5 条决定、验证和修改；Plan Mode 指令在压缩后重新注入，分支内已有时不重复注入 |
| 验证指纹 | 遵循 `.gitignore`；符号链接按链接本身记录，不跟随；未变文件按大小与两个时间戳复用摘要 |
| 子代理 | 限流、过载、网络等暂时性 provider 错误最多重试 3 次（2 秒起指数退避，等待期间释放执行名额），失败的尝试不进入线程历史；额度与计费错误不重试 |
| 路径 | 读取先把符号链接解析到真实路径，再套用同一工作区边界和逐级检查；写入路径上的符号链接仍然拒绝 |
| 外部工具 | 声明了 `readOnlyHint` 的工具在 Plan Mode 和 Read-Only 下可用，并且不再逐次审批。该标注是工具服务器的自述，套件无法验证 |
| 加载 | 入口发现 `src/` 下的文件比本进程首次加载时新，会在会话开始时提示重启 Pi |
